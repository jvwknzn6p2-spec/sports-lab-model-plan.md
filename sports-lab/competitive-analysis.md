# 競合分析 — 類似3サービスの分解と、我々の設計への反映

_調査日: 2026-07-25。X / note / 各サービスサイトの公開情報にもとづく。_

同じ領域（野球データ + AI + 期待値ベッティング）で先行している3つのサービスを分解し、
「取り込むべき設計」と「真似してはいけない設計」を切り分ける。結論は §4 の実装差分表。

---

## 1. mat / 期待値BETの鬼 — note (@mat7772384197)

| 項目 | 内容 |
|---|---|
| 対象 | 野球 NPB/MLB、海外サッカー、NBA の**ハンデ戦** |
| 主張 | 「期待値指標を独自の演算にて算出」 |
| 中核主張 | 「中長期収支が、**控除率10%を差し引いても、なお、プラス**となるよう全て計算」 |
| 固定記事 | 「**期待値指標の経時的変化について**」 |
| 規模 | 110フォロー / 78フォロワー（個人・小規模） |

### 分析

**3サービスの中で唯一、控除率（vig / オーバーラウンド）を明示的に扱っている。** これは技術的に最も重要な差。

ブックメーカーの提示オッズは合計100%を超える。1.91 / 1.91 の two-way マーケットは
52.4% + 52.4% = 104.8% を意味し、この超過分が胴元の取り分。
**提示オッズと自分のモデル確率を直接比べると、測っているのは「モデルのエッジ + 胴元のマージン」**であって、
実際に回収できるエッジではない。正しい比較対象は控除率を除去した後の市場確率。

さらに「10%」という水準設定が現実的。Pinnacle のような低マージンの店なら2%前後だが、
日本から使える多くの環境では5〜10%が普通で、そこを基準に置くのは正しい保守性。

数字で言うと、**控除率10%（両サイド 1.80）の市場で損益分岐に必要なモデル確率は 1/1.80 = 55.6%**。
公正確率50%に対して**5.6ポイントのエッジが必要**という意味で、これは相当高いハードル。
3ポイント程度のエッジは、見た目が良くてもこの市場では負ける。

「期待値指標の**経時的変化**」への言及は CLV（Closing Line Value）の概念に近い。
オッズは試合直前に向けて動き、早い段階で取ったエッジは時間とともに消える。
予測を**タイムスタンプ付きで記録**しないとこの効果は測定できない。

### 弱点

- 手法が非公開（「独自の演算」）。第三者検証が不可能。
- バックテストの公開なし。サンプルサイズ不明。
- 「控除率10%を引いてもプラス」は主張であって、証拠が示されていない。

## 2. スポーツ勝率研究所 / WINSportsAI — X (@shoritukb) + jbsports.jp

| 項目 | 内容 |
|---|---|
| 開始 | 2026年6月（X）、データは2026年5月19日以降 |
| 規模 | 1,030フォロー中 / 115フォロワー |
| サイト構成 | ダッシュボード / 試合別 / **方法論** / **結果** / 編集部 |
| 公開データ | **勝率・フェアオッズ・先発投手データ** |
| アーカイブ | 全試合（NPB/MLB/サッカー/WBC、月別・競技別フィルタ）＋ **投手別アーカイブ** |
| 試合カード | 日時・球場・リーグ / 先発投手とERA / AI予測(ホーム・アウェイ) / `H 1.52` 形式 |

### 分析

**サイト構造が最も参考になる。** 特に「方法論」と「結果」を独立したページとして常設しているのは、
このジャンルで信頼を作る唯一の正攻法。当てた予想だけを見せるアカウントとは根本的に姿勢が違う。

**フェアオッズを出しているのが技術的な要点。** `H 1.52` は小数オッズで、勝率 65.8% に相当する。
勝率%だけを出すサービスと違い、フェアオッズは市場価格と同じ単位なので直接比較できる
（提示オッズ > フェアオッズ なら妙味あり）。ユーザーに一段階の変換をさせない親切な設計。

**投手別アーカイブの存在は、先発投手が最大の説明変数だと理解している証拠。** 設計思想として正しい。

### 弱点

- **ERAを前面に出している。** ERAは守備力・被BABIP・残塁率といったノイズに汚染されており、
  投手本人の実力の予測指標としては弱い。FIP / xFIP / SIERA のほうが翌試合の予測力が高い。
  これは我々がベースラインモデル（§4.1）で優位を取れる具体的なポイント。
- 信頼度ランクに相当するものが見当たらない。すべての予想が同じ重みで並んでいる。
- EV・控除率の扱いが公開情報からは読み取れない。フェアオッズは出しているが、
  「で、これは賭ける価値があるのか」の最後の一歩がない。

## 3. プロ野球AI予想 — X (@sportsAIyosou) + sportsyosou.ai

| 項目 | 内容 |
|---|---|
| 開始 | 2026年4月、認証済みアカウント、439フォロワー |
| 中核 | 「**6つの最新AI**が野球の試合を予測」「世界各国の最新機械学習モデルを採用」 |
| 機能 | 試合前予想・**リアルタイム解説**・**勝率変動に対応**・**ハンデ入力可能** |
| 課金 | 3日間無料 → 会員登録（有料SaaS） |
| 訴求 | 「AI的中ランキング — どのAIも**的中率が約70%**」（7/14〜7/19） |

### 分析

**プロダクトとしての完成度は3つの中で最も高い。** 有料SaaS、認証済みアカウント、
リアルタイム更新まで実装している。

技術的に重要なのは2点：

1. **「ハンデ入力可能」** — 任意のハンデラインで価格を出せるということは、
   内部で**完全なスコア同時分布を保持している**（あるいは保持すべき）ことを意味する。
   「勝率」「-1.5をカバーする確率」だけを数えて返す実装では、ユーザーが -0.75 を入れた瞬間に破綻する。
   これは我々の実装方針を直接左右した（§4）。
2. **「勝率変動に対応」** — 時系列で予測を更新している。mat の「経時的変化」と同じ方向。

### 重大な注意 — 「的中率70%」は指標として無意味

これは**真似してはいけない設計**の代表例。

- **的中率はオッズを無視している。** 1.20倍の本命ばかり選べば的中率83%でも期待値はマイナス。
  逆に的中率40%でも3.0倍を取り続ければ大きくプラス。**的中率とROIは別物**であり、
  的中率を主要KPIに据えると、モデルは自動的に「本命を選ぶだけの機械」に最適化されていく。
- **「6つのAI」のうち最良を事後的に選ぶと的中率は自動的に上がる**（多重比較 / チェリーピッキング）。
  6つ試して最も良かったものを見せるなら、それは性能ではなく選択バイアス。
- **7/14〜7/19の6日間はサンプルとして統計的にゼロに等しい。** NPBなら1日6試合、6日で36試合程度。
  真の的中率が50%のコイン投げでも、36試合で70%以上出る確率は決して無視できない。
  「驚異的な記録」と呼べる水準ではない。

我々は的中率を主要KPIにしない。測るのは **ROI / CLV / キャリブレーション**（§4.4）。

## 4. 我々の設計への反映 — 実装差分

分析の結果を `@workspace/sim`（build step 5）に反映済み。

| 競合から学んだ点 | 出所 | 我々の実装 |
|---|---|---|
| 控除率を除去してからEVを測る | mat | `removeVig()` — multiplicative / additive / power / Shin の4手法。`assessValue()` が控除後エッジを返す |
| フェアオッズをそのまま出す | WINSportsAI | 全マーケットが `fairDecimal` / `fairAmerican` を持つ |
| 任意ハンデ・任意トータルに対応 | sportsyosou.ai | 完全同時分布を保持し、`priceHandicap()` / `priceTotal()` が任意ラインを再シミュレーションなしで価格付け（アジアン1/4ラインを含む） |
| 予測の経時的変化を追える | mat | 全予測に `generatedAt` と `inputsHash` |
| 方法論と結果を公開する | WINSportsAI | このリポジトリと `model-plan.md` そのもの |
| 的中率をKPIにしない | （反面教師） | MC標準誤差を併記し、§4.4 でROI・キャリブレーションを測る |
| ERAに依存しない | （反面教師） | ベースラインモデル（step 4）でFIP系指標を使う — 未実装、次の課題 |

### 3サービスの誰もやっていない差別化

1. **モンテカルロ標準誤差の明示。** 10,000回試行では確率の標準誤差が±0.5%ある。
   「+1.1%のエッジ」はノイズと区別できない。全マーケットが `standardError` を返し、
   `simsForMarginOfError()` が必要試行回数を計算する。**エッジをノイズと区別できないサービスは、
   自分が何を主張しているか分かっていない。**
2. **得点はポアソン分布ではない。** MLBの1チーム得点は平均4.5に対し分散9.5。
   ポアソン（分散=平均）を使うと裾が細くなりすぎ、トータルとランラインを系統的に誤る。
   負の二項分布（ガンマ・ポアソン混合）を使用。
3. **9回裏の非対称性。** ホームチームはリードしていれば9回裏を打たない。
   これを無視すると期待得点合計が約0.2点上振れする。実測で **+1点差の発生率が15.3% → 19.8%** に変わり、
   ホームの -1.5 カバー率は 34.6% → 30.3% と**4ポイント以上**動く。
   ランラインを扱うなら無視できない。
4. **両チーム得点の相関。** 風・球場・ストライクゾーンは両チームに同じ方向に効くため、
   スコアは弱く正相関する。無視するとトータルの分布が細くなりすぎる。
5. **決定論的シード。** 同じ入力から同じ確率が再現される。これがないとバックテストは
   モデルの実力ではなくシミュレーションのノイズを測ってしまう。

## 5. 我々が現時点で持っていないもの（正直な整理）

競合が持っていて我々にまだ無いもの:

- **稼働しているデータパイプライン。** 3サービスとも毎日実データを取得して動いている。
  我々は step 1〜3（スケジュール・データ取得・検証）が未実装。**これが最大の差**。
- **公開された実績。** WINSportsAI の「結果」ページに相当するものがない。step 8 のバックテスト待ち。
- **リアルタイム更新。** sportsyosou.ai の「勝率変動に対応」に相当する機能。
- **NPB対応。** 現在の較正値（平均4.5点・分散9.5）はMLB基準。NPBは得点環境が異なるため
  `dispersionK` をリーグ別に較正し直す必要がある。

シミュレーションの精度で先行しても、データが流れていなければ予測は1件も出ない。
次の優先順位はモデルの高度化ではなく **step 1〜3 のデータ基盤**。
