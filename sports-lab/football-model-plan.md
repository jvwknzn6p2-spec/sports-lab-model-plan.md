# サッカー予想モデル計画（Football Model Plan）v0.1 — 2026-09-02

Founder 承認プラン（2026-09-02）の Month 2–3 に当たる「サッカー MVP」の技術計画。
野球（VORTE EV / AI Sports Lab）で確立した規律 — 封緘・追記専用台帳・全件決済・
ウォークフォワード測定・基準モデル比較 — をサッカーへ移す。
競合（Ocup Football Analysis）ができないこと＝**全部記録して測って見せる**を核にする。

## 1. 目的と対象

- 対象: **J1 / J2**（日本市場の穴。Ocup の構造化 10 リーグに日本は無い）と
  **欧州 5 大リーグ**（プレミア / ラ・リーガ / セリエ A / ブンデス / リーグ・アン）
- 出力（Ocup の固定 8 項目を踏襲し、数字は本物のモデルから出す）:
  1. 最も可能性の高い結果と見通し
  2. 勝ち / 引き分け / 負け の確率（W/D/L）
  3. スコアシナリオ 5 つ（スコア行列の上位 5 マス）
  4. 両チームの期待得点（λ, μ）と 2.5 超・両チーム得点の確率
  5. 主要因（攻撃力・守備力・ホーム補正・直近の形）
  6. 当日情報（負傷・出場停止・予想スタメン）— 別レイヤで取得、未確認は未確認
  7. 信頼度と変動性
  8. 結果を変え得る要因
- **しないこと**: ベッティング助言。公開面の文言は野球と同じ「分析専用」で固定

## 2. モデル

### 2.1 中核: Dixon-Coles（実装済み・`lib/football-model`）

- λ_home = exp(attack_h + defense_a + γ)、μ_away = exp(attack_a + defense_h)
- P(h, a) = Poisson(h; λ) Poisson(a; μ) τ(h, a; ρ)。τ は 0-0 / 1-0 / 0-1 / 1-1 のみ補正
- 重み付き最尤推定（時間減衰 ξ、既定 0.0065/日 ≈ 半減期 107 日）。解析勾配の勾配上昇。
  外部依存なし・決定的
- リーク防止: `asOf` より前に始まった試合だけを学習に使う（テストで固定:
  未来の試合を足しても推定が 1 ビットも変わらない）
- W/D/L・スコア上位・期待得点・BTTS・Over 2.5 は同じスコア行列から出る

なぜ Elo ではないか: サッカーは 3 値で引き分けが約 25% あり、野球の
`DRAW_PROBABILITY`（NPB 0.075 の定数）方式では足りない。スコア行列から
W/D/L と任意スコアを同時に導ける Dixon-Coles が業界標準で、Ocup が同梱している
指標群（ホーム/アウェイ別攻守・BTTS・クリーンシート率・スコア分布）はまさにこの
モデルの入出力そのもの。

### 2.2 次の層（測ってから採用。野球の規律どおり shadow → 対照 → 格上げ）

1. **xG 入力**: 実得点の代わりに xG（または実得点と xG の混合）で attack / defense を
   推定する。野球の「先発投手」に相当する最も効く公開特徴量と見込む
2. **市場ブレンド**: クロージングオッズの含意確率とモデルの加重平均。野球の実測
   （市場 Brier 0.2432 vs 正準 0.2476・ブレンドは市場比重に単調で改善）から、
   サッカーでも市場超えは前提にせず「ブレンド＋較正の質」で測る
3. 休養日・移動距離・欧州カップ戦の翌週 — 野球の休養日特徴量と同じく、測って雑音なら見送る

### 2.3 採らないもの

- 対戦相性（H2H）: 野球で測定して雑音と区別できなかった（2026-08-31）。サッカーでも
  同一ペア年 2 試合では推定できない。求められたら「統計的に確認できない」と答える
- LLM 生成の確率: 数字はモデルからのみ。LLM は説明文の生成に限定

## 3. 測定（実装済み・`evaluate.ts`）

- **主指標は RPS（ranked probability score）**。多値 Brier・log loss を併記。
  的中率は Wilson 95% 区間つきで、単独で読まない
- ウォークフォワード: 試合日ごとに「その日より前」で学習し直して当日を予測
- 基準 1: 学習期間の W/D/L 頻度（これを下回るモデルは何の情報も足していない）
- 基準 2（データ導入後）: クロージングオッズの含意確率
- ウォームアップ（既定 100 試合）を成績に混ぜない
- 成績を CI の合否に使わない。CI が見るのは既知解・リーク検査・指標の性質

## 4. データ（未着手・Month 2 の最初の分岐点）

| 用途 | 候補 | 備考 |
|---|---|---|
| 試合結果（欧州） | football-data.co.uk の CSV | 無料・クロージングオッズ列あり・数十季 |
| 試合結果（J1/J2） | Jリーグ公式データサイト / FBref | J は football-data.co.uk に無い。取得手段の確認が最初 |
| xG | Understat（欧州 5 大）/ FBref（Opta 提供） | 利用規約の確認必須。J の xG は入手性 UNKNOWN |
| 当日情報 | Web 検索（エージェント層） | モデルの確率には入れない。説明にのみ使う |
| オッズ（封緘前） | The Odds API（野球の odds.yml と同じ） | soccer_* キー。無料枠との兼ね合いで対象リーグを絞る |

取り込みの規律は野球と同じ: 取得時刻（fetched_at）を残す・封緘（kickoff − N 分）より後の
情報を予想に入れない・欠損は埋めずフェイルクローズ。

## 5. 台帳と公開（Month 2–3）

- 予想の台帳・封緘・決済・実績カードは VORTE EV の機構（`handiedge`）を流用する。
  サッカー用に必要な差分: 3 値の結果（W/D/L）、90 分（延長・PK を除く）基準の決済、
  RPS 集計ビュー、カードの 3 値表示
- 公開は野球と同じ経路（archive ブランチ `publish/`、note / X）。1 日 1 カード、外れも出す

## 7. 既知の限界（正直に書く）

- 実データでの成績は**まだ無い**。合成データの検証は「実装が正しい」ことしか示さない
- サッカーの市場は厚く、モデル単体で市場を上回ることは世界的に稀。商品価値は
  「確率の質を測って見せること」に置き、勝率の高さを売り文句にしない
- J リーグの xG・オッズの入手性は未確認。手に入らなければ J は得点ベースのみで始める
